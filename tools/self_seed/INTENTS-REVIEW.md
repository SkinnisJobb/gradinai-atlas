## include

### `atlas:work-rolls-up` (principle): Work rolls up, never down

Reason: how rollups work in the product (ADR 0028)

> A workitem bound to a node appears there and on every node containing it, and on nothing inside it. The invariant this buys: if a node's board shows a containment-derived item, that node's numbers count it. A fourth `above` bucket pushing an ancestor's work down onto descendants was proposed and rejected.

### `atlas:oss-work-graph` (outcome): A self-hostable, open-source work and context layer for humans and their agents

Reason: the product's purpose

> Atlas is self-hostable and open source. The core is the work: the work hierarchy (Epic > Feature > Story > Task > Sub-task), the board, a REST API and an MCP server, so an agent reads and writes the same work a person sees, within limits a person sets. Everything else is an add-on an install turns on when it needs it: context retrieval, single sign-on, guardrails, CI integration. The source is open and Atlas documents itself, so a team can change Atlas with its own agents. The product ships without anyone's world in it: an instance is configuration and data, never code.

### `atlas:agents-propose-humans-commit` (principle): Agents propose; humans commit

Reason: the product's core rule for agents (ADR 0032)

> An agent may read anything Atlas holds and propose any change to it. Committing a change that alters what other work is measured against — an intent, a binding, a scope decision, acceptance criteria — stays a human act. A human commits by doing it, by approving an agent's proposal (for acceptance criteria: one click on the board), or, where an install opts in (`ATLAS_ACCEPTANCE_AGENT_WRITE=attested`), by an approval the agent must cite by name and quote, which Atlas records with the change. Read-only is the default for any credential an agent carries.

### `atlas:context-minimal` (outcome): Give an agent the fewest tokens it needs to act correctly

Reason: the product's direction: a minimal context layer for agents

> Atlas is becoming an enterprise context layer, and token consumption is the hurdle. Give an agent the fewest tokens that let it act correctly: curated knowledge kept current, pointers rather than payloads, budgets as parameters, and one task-scoped read instead of exploring. Measure bytes before and after any read-path change. The reasoning, and what makes other assistants expensive and wrong, is in ADR 0040.

### `atlas-backend:no-write-back-to-git` (non-goal): Atlas does not write data back into git

Reason: a product design decision

> The git export was built, verified and removed the same day. It was not a backup — it covered no auth, override, probe or derived state — and not an audit trail, because snapshot diffs cannot say who or when. Auditing's real answer is the `graph_event` table beside `auth_event`, which shipped on 2026-08-24 with one enforced writer, `app.record_graph_event`.

### `atlas-backend:postgres-is-authoritative` (constraint): Nothing Atlas owns lives outside the Atlas database

Reason: a product design decision (ADR 0029)

> The Atlas database (PostgreSQL, hosted wherever the install chooses: the bundled container or a managed service) is the source of truth for everything Atlas owns. Node documentation, the backlog, its acceptance criteria and its recorded results are all rows. The three importers were deleted because a second run did not top the database up — it reverted the database to the files. Nothing in this repo can now overwrite the database from a file, and nothing added should be able to. An add-on may keep a derived copy elsewhere (a vector index, a hosted model's index) only if it can be rebuilt from the database and Atlas works without it.

### `atlas-context:pointers-within-budgets` (constraint): The context answer is pointers within budgets

Reason: how the context answer is shaped (ADR 0044)

> The context answer is pointers within budgets: every part is bounded by a parameter and says when it was cut; the full text is one atlas_get or atlas_doc_read away.

### `atlas-frontend:no-module-encodes-the-graph` (principle): No module may encode the graph

Reason: a rule for the board's code

> Read the graph from `/api/*`. A type vocabulary is defensible presentation config; a node id is not. If a module needs to name a node in order to work, that is a missing endpoint, not a constant.

### `atlas-frontend:layout-is-judged-not-measured` (constraint): Layout is judged by a human, not measured by an agent

Reason: how a board layout change is verified

> An automated browser tab runs backgrounded, so `requestAnimationFrame` is throttled, so D3 transitions never advance and every node reports `translate(0,0)`. Node counts, the element-id inventory, computed styles, panel widths and real API writes are reliable. Layout, zoom, pan, collapse and map anchoring are not — stage those and ask.

### `atlas-frontend:render-names-verbatim` (constraint): `node.name` renders verbatim

Reason: a rule for the board's rendering

> Names carry two registers: prose naming a concept for a human, and the identifier a thing answers to elsewhere — one you can paste into `docker exec`. An uppercase-first transform corrupts every identifier and makes the map disagree with the panel, the API and search. Violations are reported, never mangled.

### `atlas-identity:token-belongs-to-the-human` (principle): A token belongs to a person, who stays accountable

Reason: the product's token model (ADR 0034)

> A service token belongs to an agent's OWN account, and that account records the person accountable for it. Both halves matter, and collapsing them into one sentence is what put a false premise in EPIC-atlas-contributor-onboarding for six days: "belongs to the human" is a claim about ACCOUNTABILITY, never about identity. `admin bot add` creates a distinct `auth_user` per agent and refuses a person outright; `auth.py` refuses any Bearer token whose owning account is not `is_service`. Since ADR 0034, `auth_user.person_user_id` records who is answerable, grants inherit from person to bot, ROLE never does, and disabling a person disables their agents. An owner holds no grants, so an owner's agent inherits an EMPTY set — linking makes it less capable, not more. Two independent bounds apply to every machine caller: scopes bound what it may DO (enforced since 2026-08-15 for every non-session principal, an unmapped route failing closed), and grants bound what it may SEE. Neither removes the accountability of the person who minted it.

### `atlas-mcp:facade-not-second-brain` (constraint): The MCP holds no business logic and no copy of the graph

Reason: the MCP service's design (ADR 0033)

> Every verb atlas-mcp exposes is a call to atlas-api. No validation rule, no rollup, no projection and no cached copy of the graph lives in this service. If a tool needs something the API cannot answer, that is a missing endpoint and it gets built in atlas-api -- not worked around here. A facade that starts deciding things becomes a second implementation of the graph, and the two will disagree.

### `atlas-retrieval:atlas-complete-without-it` (constraint): Atlas is complete without it

Reason: the add-on's contract (ADR 0044)

> Semantic retrieval is an add-on, never a requirement. With it off, or on but broken (no pgvector, no endpoint, the embedder down), Atlas boots, serves and searches exactly as it does without it; nothing in the core imports, calls or requires it, and its state is reported as information, never as red. Default off; an instance enables it by configuration only.

### `atlas-signals:probes-and-health-out-of-scope` (non-goal): Probes and health are out of scope

Reason: the scope of the signals area

> "Right now we should focus on presenting information so people can start working and understanding the projects." The `probe` and `probe_result` tables and the static `attributes.health` hints stay exactly as they are: do not build on them, and do not file bugs against them.

### `atlas-work-store:keep-the-id-scheme` (non-goal): A unified, type-free workitem id scheme

Reason: the product's id scheme

> Slug ids for epics and stories (`EPIC-project-atlas`, `STORY-atlas-object-graph`), numbers for tasks (`TASK-850`). Flattening them, into `EPIC-XXXX` numbers or a type-free `ID-XXXXX`, was considered and rejected. No code parses the prefix (type comes from the `type` column), so unifying simplifies nothing and costs legibility in every edge dump, log line and commit. The split matches lifespan: tasks are numerous and disposable, stories and epics are referred to in prose for months. Reopen only if reclassifying a task as a story, or the reverse, becomes common.

### `atlas-world-model:contains-is-part-of` (principle): `contains` means "is part of" — nothing else

Reason: the world vocabulary (ADR 0030)

> It is the product decomposition. Not ownership, not a permission grammar, and not deployment — where something runs is `hosted_on`'s job. A thing that is not a part of the product does not get a `contains` edge, however convenient the nesting looks.

### `atlas-world-model:node-holds-open-work` (constraint): Count OPEN workitems, and never let a count trigger a split

Reason: how node load is counted

> Status not `done` or `cancelled` -- the same lens the board's age-out filter uses. **Never count lifetime**: a lifetime count only rises, so a threshold on it fires in every node eventually just from work being finished, splitting the tree forever while findability never actually got worse.
>
> **The 5-25 ceiling this constraint used to state was RETIRED on 2026-08-15** (ADR 0030 amended). It fired on `atlas-mcp` the moment an epic was filed against it, which is the failure mode rather than the rule working: a node acquires work because work exists, not because it became hard to read. A number cannot tell you whether work is findable.
>
> So: split a node when finding the work in it actually gets hard, and say what got hard. A count is a description, never a trigger.

### `atlas-world-model:ask-before-binding` (constraint): Ask before assigning a binding

Reason: a rule for agents binding work to nodes

> The pause on being asked to map things by hand ended with ADR 0030; the ask-first rule did not. A binding decides where work shows up for everyone who reads the board, so it is not an agent's call to make on someone else's behalf.


## exclude

### `atlas:no-backup` (non-goal): Backup is out of scope

Reason: one estate's policy, not the product's; the OSS install ships a backup profile

> There is no copy of the database anywhere, and that is a decision rather than an oversight — reaffirmed with the size of it in front of him, auth tables included. Losing the server means losing the work, and that is accepted. Do not propose `pg_dump`.

### `atlas:postgres-everywhere` (constraint): A test that needs a database needs a real one

Reason: a rule for contributors to Atlas's own test suite, not for the product

> Atlas runs on Postgres and always did; SQLite was only ever the verify scripts' scratch file, and it is gone along with every fallback and dialect branch. `testdb.py` hands each script a real Postgres — an explicit URL, else a disposable container, else a hard failure. Never a skip, and never a substitute.
