Crunch week

Skeleton page. The full handbook is written in a later pass; what is here is short and correct. The full guide is docs/oss/guides/crunch-week.md in the Atlas repository.

Crunch week is a release mode for a set time. While it is on, a change that passes CI deploys to production without the staging and pre-production steps chosen from the install's guardrail matrix. It is off by default, and it ends by itself at the end time.

Who can turn it on

Only the instance owner, in a browser session, entering their password on every change. The control is a tab in Settings. No token, whatever its scopes, and no MCP tool can read or change it.

What you set

  • When: start now or at a scheduled time, and an end time or a length. The server's clock decides; at most 31 days.
  • Backups: none (the default), once at the start, before every production deploy, hourly or daily, with a retention in days. Each backup is restored into a temporary database and counted before it counts as a backup.
  • Skipped environments: non-production environments of the guardrail matrix in force. With no matrix applied, nothing is skipped.

What still holds

  • CI is still required, and production keeps the gate the matrix gives it.
  • Agents never hold deploy rights in production.
  • Atlas deploys nothing itself: you generate the crunch variant of the pipeline with atlas-admin cicd generate --crunch ..., commit it, and generate again without it afterwards.

What it records

Activating, changing, extending and ending, by hand or by expiry, each write one graph event and one Accepted ADR on the atlas-system node. While it is on, every signed-in person sees a banner on the board saying until when.
