Security

Skeleton page. The full handbook is written in a later pass; what is here is short and correct.

One gate, deny by default

Every request to atlas-api passes one authorization middleware. A route is closed unless it is on a short, fixed list of public paths: the landing page, sign-in, the privacy notice, the liveness probes, and the pages of /docs when ATLAS_PUBLIC_DOCS=1. A machine caller gets 401, never a redirect to a login page.

People and agents

  • People sign in with a password, or with single sign-on through OpenID Connect.
  • Agents use their own bearer token, minted with atlas-admin or under Settings. A token carries scopes (read, write, admin) and is linked to the person accountable for it.
  • With ATLAS_RBAC=projects, a project is visible only to the people and groups bound to it. A hidden node and a missing one answer the same 404.

The public handbook

/docs serves only the files generated from this handbook into the image: a fixed list of pages read from disk, with no database access and nothing a user can edit. The documents stored on these nodes in the database are separate copies; editing them changes the board, not /docs.

At the edge

The ingress in deploy/oss terminates TLS and sets the browser security headers, including a Content-Security-Policy that allows no inline script.
