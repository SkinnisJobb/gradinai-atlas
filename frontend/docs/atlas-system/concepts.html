Concepts

Skeleton page. The full handbook is written in a later pass; what is here is short and correct.

Atlas keeps one graph in Postgres: nodes joined by typed edges. Everything the board shows and every tool an agent calls reads and writes that graph through the same API.

Two families of node

  • World nodes describe what exists: an org, a project, a system, a service, a db, a host, a component, a capability, an agent. They are arranged by contains edges.
  • Workitems describe what is being done: an epic contains story items, and a story contains task items. A workitem is attached to the world by a works_on edge, never by contains.

Work rolls up: a system node is usually not worked on directly; the work bound to its children shows on it by containment.

What a node carries

  • A summary, an abstract and a detail: the short to long description of the node.
  • Documents: markdown pages stored with the node and listed in its docs attribute. This handbook is the documents of the atlas-system node and its children.
  • Intents: durable statements of purpose (a constraint, a principle, a non-goal or an outcome) that bind the node and everything below it.

Where you see it

  • /board is the board: a graph of the world, a work board scoped by it, and a node panel.
  • /docs is this handbook as a static site, generated from the same documents.
  • Agents reach the same graph through the MCP server; see Agents.
