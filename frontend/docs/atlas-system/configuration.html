Configuration

Skeleton page. The full handbook is written in a later pass; what is here is short and correct.

Atlas is configured by environment variables. An install made from deploy/oss keeps them in one .env file, copied from deploy/oss/.env.example, whose comments explain every setting.

Secrets are files

Credentials are never plain environment values. Each one is a file under deploy/oss/secrets/ (written by scripts/init-secrets.sh), and the setting names the file: ATLAS_DB_URL_FILE, ATLAS_PASSWORD_PEPPER_FILE, ATLAS_TOKEN_PEPPER_FILE. The two peppers are fixed for the life of the install: a new pepper invalidates every password and every token at once.

The settings you choose first

  • ATLAS_PUBLIC_URL: the address people and agents use.
  • ATLAS_SEED: what an empty database starts with. none is an empty instance, demo adds one example project, and self adds Atlas's own world model (its parts, their documents and a set of intents, with no work); all three add this system node and its handbook.
  • ATLAS_LEGACY_V0: 0 leaves out the frozen first-generation tables and routes.
  • ATLAS_RBAC: projects puts roles on projects, with private projects by default.
  • ATLAS_PUBLIC_DOCS: 1 serves /docs without sign-in; see Security.
  • ATLAS_DISABLED_FEATURES: switches optional features off by name.

A malformed setting stops the API at start-up with a message that names the variable.
